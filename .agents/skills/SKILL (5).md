# Channels Integration (WhatsApp + Telegram)

## WhatsApp Cloud API

- Официальный Meta Cloud API, не неофициальные библиотеки (Baileys и т.п.) — стабильность важнее.
- На каждый входящий webhook — проверка подписи `X-Hub-Signature-256` ДО любой обработки тела запроса.
- Ответ `200 OK` сразу после проверки подписи, реальная обработка — в очереди (см. скилл `backend`).
- Отправка сообщений: учитывай ограничения шаблонов (WABA templates) для исходящих первых сообщений вне 24-часового окна диалога.

## Telegram Bot API

- Webhook-режим (не long polling) для прода. Проверяй secret token заголовок, который Telegram прикладывает к webhook-запросам.
- Rate limit ~30 сообщений/сек — для рассылок обязательна очередь с контролем скорости отправки, не цикл `for` с мгновенными вызовами API.
- Userbot (автоматизация личного аккаунта для рассылок) — если реализуешь, обязательно покажи в UI явное предупреждение о риске блокировки номера. Не включай эту функцию "тихо" по умолчанию.

## Общий контракт с остальной системой

Оба канала ДОЛЖНЫ нормализоваться в одинаковую форму строки `messages` до передачи в AI-оркестратор. Оркестратор (`ai-agent-core` скилл) не должен знать и не должен проверять, из какого канала пришло сообщение — это ответственность слоя `channels-integration`.

Каждое входящее сообщение обязано получить `external_message_id` — без него не сработает идемпотентность на уровне БД (см. скилл `database`).

## Чеклист

- [ ] Подпись/токен webhook проверяется до обработки тела
- [ ] 200 OK отправляется немедленно, обработка асинхронна
- [ ] Повторная отправка одного и того же webhook-payload не создаёт дубликат в `messages`
- [ ] Для Telegram userbot-функций есть предупреждение в UI
