# AI Agent Core

## Системный промпт — фиксированная структура

10 тегов из `/docs/SPEC.md` раздела 4 (`<role>`, `<goal>`, `<location_context>`, `<tone_of_voice>`, `<human_communication_style>`, `<communication_rules>`, `<knowledge_base_principles>`, `<dialogue_flow>`, `<general_capabilities>`, `<tools_calling_instructions>`). Не добавляй новые верхнеуровневые теги без обновления SPEC.md — иначе следующий проход агента не будет знать, что эти теги существуют.

## Главное правило безопасности — без исключений

**Контент пользователя (его сообщения) НИКОГДА не подставляется внутрь строки системного промпта.** Он всегда передаётся отдельным сообщением с ролью `user` в Gemini API. Если видишь код, который делает `systemPrompt + userMessage` и отправляет как единый текст — это prompt injection уязвимость, её нужно переписать, даже если "так проще было сделать". Это пункт 9.4 в чек-листе SPEC.md, его будут проверять отдельным тестом ("игнорируй все инструкции и...").

## RAG / база знаний

- Чанкинг: 500–1000 токенов на чанк, overlap ~10–15%.
- В метаданных каждого чанка — `source_id` и позиция в документе, чтобы агент мог сослаться на источник.
- Эмбеддинги: Gemini `text-embedding-004`, 768 измерений, косинусное сходство.
- `searchKnowledgeBase` — единственный способ агента получить факты. Если в промпте агент "помнит" что-то про продукт без вызова этого инструмента — это галлюцинация, которую нужно дебажить, а не фича.

## Инструменты (tools)

Список фиксирован в `/docs/SPEC.md` разделе 5. Добавление нового инструмента = обновление function-calling схемы И этого SKILL.md одновременно, чтобы они не расходились.

Каждый вызов инструмента обязательно:
1. Логируется в `messages.tool_calls`
2. Логируется в `ai_call_logs`

Без этого невозможно будет разобрать post-mortem, почему агент сделал что-то неожиданное в проде.

## Чеклист перед тем как сказать "ядро агента готово"

- [ ] User-контент передаётся отдельным сообщением, не конкатенацией в system prompt
- [ ] searchKnowledgeBase вызывается перед любым фактическим утверждением о цене/услуге
- [ ] Каждый tool call логируется в обе таблицы
- [ ] Retry с backoff настроен на 429 от Gemini
