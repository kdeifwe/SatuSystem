# Database (Supabase / Postgres)

## Источник правды

Схема целиком описана в `/docs/SPEC.md`, раздел 3. Это не пример "для вдохновения" — это финальные имена таблиц и колонок. Если меняешь имя поля — обновляешь SPEC.md в том же коммите, иначе документ и код расходятся, и следующий проход агента всё переломает.

## Жёсткие правила

1. **RLS включается в той же миграции, где создаётся таблица.** Не "сделаем потом отдельной задачей" — потом не сделают.
2. **Любая колонка типа `vector` получает индекс (`ivfflat` или `hnsw`) в той же миграции**, где создаётся колонка. Без индекса поиск работает на маленьких данных и превращается в full table scan при росте.
3. **Миграции аддитивны.** Не редактируй уже применённую миграцию — пиши новую. История миграций должна быть линейной и воспроизводимой через `supabase migration up`.
4. **Используй Supabase CLI** (`supabase migration new <name>`), а не ручной SQL через дашборд — иначе изменения не попадают в git и пропадают при разворачивании на новой машине.
5. **Naming:** таблицы — snake_case, множественное число (`leads`, `messages`); колонки — snake_case, единственное число.

## Пример RLS-паттерна (повторяй на каждой таблице с org_id)

```sql
alter table <table_name> enable row level security;

create policy "org members see only their org rows"
on <table_name> for select
using (
  org_id in (select org_id from org_members where user_id = auth.uid())
);
```
Не забывай аналогичные policy для `insert`/`update`/`delete`, если они нужны не только владельцу/админу.

## Уникальные индексы для идемпотентности

`messages.external_message_id` — unique-индекс с `where external_message_id is not null`. Это основа защиты от дублей при ретраях webhook — backend-скилл полагается именно на этот constraint, а не на проверку в коде.

## Проверка перед коммитом миграции

- [ ] RLS включён
- [ ] Индекс на внешних ключах, по которым идёт фильтрация (`org_id`, `lead_id`, `conversation_id`)
- [ ] Если есть `vector`-колонка — индекс на ней
- [ ] SPEC.md раздел 3 обновлён, если схема отличается от описанной там
