# Сценарии уведомлений Telegram — полная логика

## Группа 1: КРИТИЧЕСКИЕ (🔴 — мгновенно, нельзя пропустить)

### 1.1 Лид просит оператора / AI не справляется

Триггер: вызов инструмента `redirectToOperator(reason)`
Текст:

```
🆘 Нужен оператор
👤 Лид: {{lead.name}} ({{lead.channel}})
💬 Причина: {{reason}}
🔗 Открыть диалог: {{dashboard_url}}/leads/{{lead.id}}
```

Получатели: все admin/owner + assigned_to
Дедуп: не чаще 1 раза в 10 минут на одного лида

### 1.2 Интеграция отвалилась (канал недоступен)

Триггер: webhook канала вернул ошибку 3 раза подряд ИЛИ не получали
сообщений > 30 минут при активном канале
Текст:

```
⚠️ Канал недоступен
📡 Канал: {{channel.type}} ({{channel.name}})
❌ Ошибка: {{error_message}}
⏰ Время: {{time}}
→ Проверить настройки канала
```

Получатели: только owner/admin
Дедуп: не чаще 1 раза в час на канал

### 1.3 Лид написал, но AI молчит > 5 минут

Триггер: входящее сообщение есть, но ответа AI нет > 5 минут
(застрял в очереди, упал воркер, rate limit Gemini)
Текст:

```
⏳ AI не отвечает
👤 Лид: {{lead.name}}
💬 Последнее сообщение: "{{last_message_preview}}"
⏰ Ждёт ответа: {{waiting_minutes}} мин
→ Ответить вручную или проверить статус AI
```

Получатели: assigned_to + admin
Дедуп: 1 раз на инцидент (до следующего успешного ответа)

## Группа 2: БИЗНЕС-СОБЫТИЯ (🟡 — важно, но можно с задержкой до 1 мин)

### 2.1 Лид купил / сделка закрыта

Триггер: статус лида сменился на `won`
Текст:

```
🎉 Сделка закрыта!
👤 {{lead.name}}
📱 Канал: {{channel.type}}
🏷️ Теги: {{lead.tags}}
💼 Ответственный: {{assigned_to.name}}
🔗 Открыть карточку: {{dashboard_url}}/leads/{{lead.id}}
```

Получатели: owner + assigned_to
Дедуп: 1 раз при каждом переходе в won (если вернули из won и снова — слать снова)

### 2.2 Лид потерян / отказ

Триггер: статус → `lost`
Текст:

```
❌ Лид потерян
👤 {{lead.name}}
💬 Последнее сообщение: "{{last_message_preview}}"
📅 Дней в работе: {{days_since_created}}
→ Можно попробовать реактивацию через рассылку
```

Получатели: assigned_to + admin
Дедуп: 1 раз при переходе в lost

### 2.3 Новый лид пришёл (первое сообщение)

Триггер: создана новая запись в `leads` (первый контакт)
Текст:

```
🆕 Новый лид
👤 {{lead.name || "Без имени"}}
📱 Канал: {{channel.type}}
💬 Первое сообщение: "{{first_message_preview}}"
⏰ {{time}}
```

Получатели: admin (не спамить всем при каждом новом лиде)
Дедуп: 1 раз на лида навсегда
Настройка: можно выключить отдельно (при большом потоке лидов)

### 2.4 Лид оставил номер телефона / email

Триггер: вызов `update_lead_info` с полями phone или email
Текст:

```
📞 Лид оставил контакт
👤 {{lead.name}}
{{#if phone}}📱 Телефон: {{phone}}{{/if}}
{{#if email}}📧 Email: {{email}}{{/if}}
🔗 Открыть: {{dashboard_url}}/leads/{{lead.id}}
```

Получатели: assigned_to
Дедуп: 1 раз на тип контакта на лида

## Группа 3: ОПЕРАЦИОННЫЕ (🟢 — информационные, можно пакетом)

### 3.1 Повторные касания исчерпаны

Триггер: `repeat_touches.attempts_sent >= max_attempts`
Текст:

```
🔁 Повторные касания исчерпаны
👤 {{lead.name}}
📊 Отправлено попыток: {{max_attempts}}
💬 Лид так и не ответил
→ Принять решение: закрыть или оставить
```

Получатели: assigned_to
Дедуп: 1 раз на цикл (до следующего ответа лида)

### 3.2 Лид написал после долгого молчания (реактивация)

Триггер: входящее сообщение от лида, у которого последнее сообщение
было > 7 дней назад
Текст:

```
💫 Лид вернулся!
👤 {{lead.name}}
⏰ Молчал: {{days_silent}} дней
💬 Написал: "{{message_preview}}"
```

Получатели: assigned_to + admin
Дедуп: не чаще 1 раза в 24 часа на лида

### 3.3 Запланированное сообщение не отправилось (failed)

Триггер: `scheduled_messages.status = 'failed'` после 5 попыток
Текст:

```
❌ Запланированное сообщение не доставлено
👤 Лид: {{lead.name}}
💬 Текст: "{{message_preview}}"
❌ Ошибка: {{last_error}}
→ Отправить вручную
```

Получатели: admin
Дедуп: 1 раз на запись scheduled_messages

### 3.4 AI работает вне рабочих часов (если настроен график)

НЕ уведомление — это поведение working_hours (silent/auto_reply/queue).
Но если оператор вручную ответил вне часов → уведомить его,
что AI сейчас на паузе по расписанию и когда включится обратно.
(реализуется как системное сообщение в UI, не Telegram)

## Группа 4: ТЕХНИЧЕСКИЕ АЛЕРТЫ (только owner/admin, через отдельный конфиг)

### 4.1 Gemini API rate limit / ошибка

Триггер: Gemini вернул 429 или 500 трижды подряд
Текст:

```
🤖 Проблема с AI
❌ Gemini API: {{error_code}} {{error_message}}
⏰ {{time}}
→ Диалоги не обрабатываются автоматически
```

### 4.2 Баланс Gemini API заканчивается

(если есть возможность мониторить через API — добавить, иначе skip)

### 4.3 Воркер завис (нет обработанных сообщений > 15 минут)

Триггер: pg_cron healthcheck — последняя запись в ai_call_logs
старше 15 минут при наличии pending сообщений
Текст:

```
⚠️ Воркер не отвечает
⏰ Последняя активность: {{last_activity_ago}} минут назад
📥 Необработанных сообщений: {{pending_count}}
→ Проверить Supabase Edge Functions / логи
```

## Приоритет реализации

Сначала (без них система бесполезна):

1. operator_needed — самое частое и критичное
2. deal_won — ради этого вся система
3. channel_down — без канала ничего не работает

Потом:
4. ai_silent — диагностика
5. new_lead — операционный контроль
6. contact_received — квалификация лида
7. repeat_touches_exhausted — воронка продаж

В последнюю очередь:
8. deal_lost, lead_returned, scheduled_failed
9. ai_error, worker_down — технические алерты
