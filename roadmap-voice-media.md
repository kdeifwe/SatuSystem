# Roadmap: Voice / Media Handling

## Что сделано
- Голосовые сообщения WhatsApp и Telegram теперь транскрибируются через OpenAI (`gpt-transcribe`).
- Оригинальные аудиофайлы сохраняются в приватный Supabase bucket `messages-media`.
  - В базе данных хранится путь в хранилище (`media_url`), а не signed URL.
- При ошибках загрузки/транскрипции отправляется дружелюбное сообщение пользователю вместо молчаливого возврата.
- Раньше входящие voice/image/document события часто молча отбрасывались (msg.text пустой → `return`). Это приводило к жалобам, что агент "не понимает голосовые"; теперь голосовые обрабатываются.

## Что осталось
- Изображения / Vision: добавить обработку изображений (скриншоты оплаты, чеки) с использованием подходящего OCR/vision модели (следующая фаза).
- Документы (PDF/DOC): добавить обработку вложенных документов, извлечение текста/ключевой информации — фаза после изображений.
- Baileys-клиенты: в кодовой базе обнаружены `lib/channels/baileys-*.ts`. Они не входят в `Spec.md` как официальная интеграция; требуется отдельный анализ использования и рисков (включая риск бана при использовании неофициальных клиентов).

## Замечания / Риски
- Для STT требуется корректно настроенный `OPENAI_API_KEY` в окружении. Без него транскрипция не будет работать и webhook будет уведомлять пользователей об ошибке.
- Хранение оригиналов в приватном бакете гарантирует, что UI/клиент будет генерировать signed URLs по требованию, а не хранить их в `messages.media_url`.

## Предложенные следующие шаги
1. Добавить поддержку изображений (vision) — оценить модели и стоимость.
2. Добавить обработку документов (PDF) и извлечение ключевых полей.
3. Провести ревью `lib/channels/baileys-*.ts` и принять решение о поддержке/удалении/изолировании.
4. Улучшить typing для `saveBufferToSupabase` (заменить `any` на точный тип Supabase клиента).
